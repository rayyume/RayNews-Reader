# RayNews 当前架构与设计边界

本文记录当前仍适用、且仅靠历史实施计划不易看出的设计理由。具体行为以代码和测试为准；历史方案可从 Git 历史查阅。

## 运行与数据边界

- Nginx 提供 PWA 静态文件，并把文章/图片请求转给 `refresh_server.py`、把认证/设置/AI 等请求转给 `web_server.py`。`supervisord` 守护这三个进程；抓取由刷新服务启动独立的 `fetcher.py` 进程。参见 `nginx.conf`、`supervisord.conf`。
- `/app/data` 是持久化边界，包含文章、用户与 AI 数据库、抓取状态和图片缓存。镜像重建不能代替数据备份；删除历史文章和缓存应走应用提供的清理流程。
- 文章与用户/设置分属不同的 SQLite 数据库；连接按线程管理，涉及竞争的状态更新使用事务。新增跨库操作时不能假设一个事务能同时提交两个数据库。

## 抓取与 AI 成本

- Telegram 消息 ID 是增量游标。首次没有游标时只导入北京时间当天的消息；后续按 ID 抓取新消息，包括中断期间的跨日消息，每轮最多翻 200 页。补抓文章按实际入库时间参与日报，而不是回填原发布日期。参见 `fetcher.py`。
- 单篇自动摘要只扫描最近 24 小时入库、尚无摘要的文章；失败记录仍需经过 6 小时退避。这个窗口限制历史积压的 AI 成本，退避控制窗口内的重试频率。参见 `web_server.py` 的 `_fetch_unsummarized_articles()`。
- 每日摘要由管理员配置的系统 AI 在北京时间 21:00 对同一时间窗口的文章生成一份全局结果，再分别分发站内通知和邮件；收件人数不应增加生成次数。生成失败有有限的自动重试，管理员可在失败后手动重试。

## 权限与外部输入

- 第一个管理员的创建必须由数据库事务决定，不能仅靠请求前查询用户数；后续注册遵循邀请码与限流规则。参见 `models.py`、`auth.py`。
- AI 结果只有服务端后台可写。用户权限在 `ai_permissions` 中由管理员维护，显示偏好在 `user_settings` 中由用户维护。有效访问取两者交集；管理员始终获得所有权限。权限每次从数据库读取，用户设置不能写入权限。
- 自动生成开关保存在全局 `app_state.ai_generation`，不依赖某位管理员的个人设置。个人 Key、共享资格、连通性复测及结果上传链路已移除。
- TTS 是用户点击触发的独立服务，配置和 Basic Auth／Authorization 凭据保存在 `app_state.system_tts_config`，不复用文本模型 Key。合成读取服务端原题、当前原文正文和访问者可见的摘要；提交、任务查询和音频读取都检查当前权限和偏好，含摘要的音频额外检查摘要访问。音频任务状态仅在单个 Web 进程内存中，MP3 临时文件位于容器 `/tmp`、不属于持久化数据边界；一小时过期、256 MB 容量上限、启动及定时清理，传输中的文件以租约保护。文章删除使任务失效，阻止后台重新发布；前端用鉴权 fetch 获取 Blob 供全局播放器使用，不把登录 Token 放到媒体 URL。
- 原始文章是公共数据，AI 标题、译文、摘要通过鉴权接口返回，使用 `private, no-store`；原文短标题、完整译名和译文短标题分别缓存。内部 `news.json` 镜像不对外公开。
- 当前原文正文以 `body_html` 为准；公开详情、迁移和 TTS 均不能用首次抓取的 `original_body_html` 覆盖它。原题变化通过数据库触发器在同一事务中清除三类标题结果、来源和各自退避，版本触发器同步通知客户端；同一原题重抓不清缓存。后台标题结果和错误写入都在写锁内核对请求使用的原题，过期请求不能恢复旧结果；正文翻译缓存内的标题不作为新原题的可信译名。
- 登录、身份验证和前台恢复统一在设置成功加载、访问状态生效后同步每日总结，不在未知权限状态下提前同步；总结请求不等待无关的标题批量读取。
- 账户迁移和新闻结果迁移分属两个数据库，各自使用事务与持久化阶段标记。旧文章结果无法可靠区分生成者，先隔离到历史表，不按管理员 ID 判断可信。重新入库的原题同步写入 `title` 和 `original_title`，并清除旧 AI 来源及时间标记；读取与迁移仅在 `title_source` 明确标记 AI 改题时使用原题快照，搜索和后台标题处理采用相同规则。迁移不改写 `body_html`：`original_body_html` 可能只是首次入库的旧摘要，不能用于推断当前正文。后台启动前必须完成迁移；恢复旧版本需恢复匹配数据库。每日总结所有查看与投递路径均检查权限及用户主开关，历史站内通知也按当前状态过滤。
- 服务端抓取的图片与 AI Endpoint 默认只允许安全的公网 HTTP(S) 目标，并逐跳验证重定向。私有 AI Endpoint 仅能通过明确设置 `AI_ALLOW_PRIVATE_ENDPOINTS` 放开；不能把历史安全方案中的“一律不支持内网模型”当作现行规则。参见 `network_safety.py`。
- 删除文章时保留 tombstone，避免旧 Telegram 消息在后续刷新中重新出现。收藏文章的图片受到缓存清理保护。参见 `fetcher.py`、`image_cache.py` 和相关删除接口。
